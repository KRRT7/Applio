# Vendored libraries

Applio carries a copy of some third-party code here, imported through the
`_vendor` namespace (the layout pip uses in `src/pip/_vendor`).

| Library | Packages | Origin |
|---|---|---|
| Deep-Live-Cam | `deep_live_cam`, `modules` | [hacksider/Deep-Live-Cam](https://github.com/hacksider/Deep-Live-Cam) `main` at the commit in [`tools/vendoring/dlc-upstream.txt`](../tools/vendoring/dlc-upstream.txt), plus the patches in [`tools/vendoring/patches/dlc`](../tools/vendoring/patches/dlc) |

## Deep-Live-Cam is upstream plus patches: never edit it by hand

`_vendor/modules` and `_vendor/deep_live_cam` are generated by
[`scripts/vendor_dlc.py`](../scripts/vendor_dlc.py) (modelled on
[kpip](https://github.com/warpforgedotco/kpip)'s `vendor_pip.py`) and
committed. The script takes upstream at the pinned commit, moves it under
`_vendor` mechanically, then applies the patches in name order with `git am`:

1. **Mechanical, in the script:** `modules/` becomes `_vendor/modules/`
   without the desktop UI (`ui.py`, `run.py`, ...); upstream's `LICENSE`
   becomes `_vendor/deep_live_cam/LICENSE`; imports are rewritten to the
   `_vendor` namespace, so the code never depends on a top-level `modules`
   package; line endings become LF.
2. **Patches:** every way Applio's copy differs from upstream, one change per
   patch, each explaining why in its message. `0001`-`0003` are the headless
   library this copy started from (Deep-Live-Cam branch `headless-library` at
   `047c551`, never pushed, so reconstructed); the rest are Applio's own
   changes, each with an `Applio-Commit:` trailer.

CI's `Vendored Deep-Live-Cam` job runs `vendor_dlc.py check`, which
regenerates both trees and fails if the committed ones differ. A daily job
applies the patches to upstream's latest `main` and opens an issue when one
no longer applies or breaks.

`_vendor/__init__.py` and this README are Applio's own and edited normally.

### Changing the vendored code

```console
uv run --no-project scripts/vendor_dlc.py sync --commit "$(cat tools/vendoring/dlc-upstream.txt)"
cd build/dlc          # branches: upstream, base (moved under _vendor), applio (base + patches)
# edit, test, commit on `applio`: one commit per change, its message saying why.
# To amend an existing patch instead: git rebase -i base
cd ../..
uv run --no-project scripts/vendor_dlc.py export   # build/dlc's commits -> tools/vendoring/patches/dlc
uv run --no-project scripts/vendor_dlc.py sync --commit "$(cat tools/vendoring/dlc-upstream.txt)"
```

Commit the patches together with the regenerated trees.

### Moving to a newer upstream

```console
uv run --no-project scripts/vendor_dlc.py sync    # latest hacksider main
```

If a patch no longer applies, `sync` stops mid-`git am` in `build/dlc`:
resolve it there, `git am --continue` (repeat for later patches), then
`export` and `sync --commit "$(cat tools/vendoring/dlc-upstream.txt)"`.
Run the test suite before committing.

## Rules

- **Imports use the `_vendor` namespace,** both from Applio
  (`from _vendor import deep_live_cam`) and inside the vendored code
  (`from _vendor.modules.x import y`). Code added by a patch follows the same
  form the script produces.
- **Dependencies are not vendored.** Deep-Live-Cam's runtime dependencies are
  declared in Applio's `pyproject.toml` (the `faceswap` dependency group).
- **Formatters leave `_vendor` alone** (see `.github/workflows/code_formatter.yml`):
  reformatting generated code would fail the check.
- **License:** `deep_live_cam/LICENSE` covers both packages. Deep-Live-Cam is
  **AGPL-3.0**; Applio itself is MIT. Distributing Applio with this code, or
  serving it to others over a network, brings the AGPL terms into play for
  the combined work. The pin plus the patch series is the corresponding
  source of the modifications.

## Runtime configuration

Deep-Live-Cam downloads its models to `DLC_MODELS_DIR`; the Live page sets
this to `rvc/models/faceswap` before importing it.
